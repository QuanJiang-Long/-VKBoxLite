# 产线 SN 烧录工装（PC 端窗口软件）方案

> 状态：待评审
> 配套设备端：`soft_sn_demo`（Air780EP + FSKV 软 SN）
> 通信通道：用户虚拟串口（`uart.VUART_0`，真机实测 = 32），115200 8N1

---

## 1. 定位

替代 SSCOM 手工发指令，做成一键式产线工装。核心诉求就三条：

1. **不会烧错** —— 一台设备只有一个 SN，四道防重防线
2. **不会漏记** —— 每烧一台必落台账，IMEI ↔ SN 可追溯
3. **工人不用动脑** —— 换设备、按一个键、看结果

设备端已有指令集，本软件是这些指令的可视化编排层，**不在 PC 端造第二套 SN 规则**：

```
R:SN              读 SN
W:SN=xxx[,FORCE]  写 SN
LOCK:SN           上锁
UNLOCK:SN         解锁（返修）
```

## 2. 功能清单

### F1 串口连接

| 功能 | 说明 |
|---|---|
| 自动枚举 | 列出本机全部 COM 口 |
| **自动识别设备口** | 逐个口发 `R:SN`，收到 `RET:SN=` 或 `RET:SN=EMPTY` 即判定为设备口。**解决"合宙虚拟口不一定是 COM4"的问题**，工人不用猜端口号 |
| 手动指定 | 自动识别失败时允许手工选口 |
| 状态指示 | 连接/断开/掉线，掉线自动标红 |
| 换设备检测 | IMEI 变化即判定换了设备，自动复位到待烧状态 |

### F2 设备探测

一键读出并展示设备身份卡：

| 字段 | 来源 |
|---|---|
| SN 状态 | `R:SN` → EMPTY / 有值 / INVALID |
| SN 值 | `R:SN` |
| 锁定状态 | 写操作返回 `locked` 时反映 |
| IMEI | 预留指令（当前设备端未提供，见 §6 待确认） |
| 芯片 UID | 同上 |

> IMEI 目前只在设备开机日志里有，串口拿不到。**这是本方案唯一的功能缺口**，见 §6。

### F3 SN 规则引擎（可配置）

| 配置项 | 说明 |
|---|---|
| 前缀 | 如 `VK` |
| 时间标签 | `YYMM`，随分配月份变化，**流水号不因此重置** |
| 流水号位数 | 建议 5~7 位 |
| 校验位 | 可选，末尾 1 位 |
| 示例 | `VK-2609-00042` 或 `VK26090000042C` |

流水号存本地 `counter.json`，**掉电不丢、永不自动重置**。

### F4 四道防重防线（本软件最重要的部分）

| # | 防线 | 防什么 | 实现 |
|---|---|---|---|
| 1 | IMEI 台账查重 | 同一台设备被重复分配新号 | 分配前查 `ledger.csv`，IMEI 已存在则跳过，直接报"该设备已有编号 XXX" |
| 2 | 计数器先占位 | 两台设备拿到同一个号 | 分配后**立即落盘** counter，再去写设备 |
| 3 | 失败号作废不回收 | 崩溃后重发旧号 | 写失败/校验失败，计数器不回退，该号永久作废 |
| 4 | 启动对账 | 计数器文件丢失或被改小 | 启动时 `next = max(counter, 台账最大流水号 + 1)` |

counter.json 损坏且 ledger.csv 也损坏 → **停机报警，绝不猜**。

### F5 烧录执行（核心流程）

```
连接 → 探测 → 台账查重 → 分配新号 → 写入 → 回读校验 → 记台账
```

- 每步结果可视化（绿勾/红叉），失败停在当步并给出原因
- 失败原因直译：
  - `char invalid` → SN 含非法字符（规则配错了）
  - `length invalid` → SN 超长（规则配错了）
  - `sn exists` → 设备已有不同 SN，需确认是否返修
  - `locked` → 设备已上锁，需走返修流程
  - `verify fail` → 写入后回读不一致（Flash 异常，该号作废）
  - 串口无响应 → 线松了/口选错了
- 写入前二次确认（防误点）
- 可选：烧录成功后自动 `LOCK:SN`

### F6 生产模式（批量）

| 功能 | 说明 |
|---|---|
| 「下一台」按钮 | 换设备后一键走完整流程 |
| 自动循环 | 可开启，探测到新 IMEI 自动开烧 |
| 大字号结果 | 成功绿/失败红，产线 1 米外看得清 |
| 班产统计 | 本次成功数、失败数、当前流水号、连续失败报警 |
| 完成后提示音 | 可选 |

### F7 返修模式

- 独立入口，与正常烧录分开记账
- 流程：`UNLOCK:SN` → 输入/分配新号 → `W:SN=xxx,FORCE` → 回读校验
- 台账里标记 `rework=true`，保留原 SN 记录（不覆盖历史）

### F8 台账与追溯

`ledger.csv` 字段：

| 列 | 说明 |
|---|---|
| time | 烧录时间 |
| imei | 设备 IMEI（防重主键） |
| sn | 烧入的 SN |
| result | ok / fail / rework |
| reason | 失败原因 |
| operator | 操作员（可配置工号） |

- 界面内可搜索（按 IMEI / SN / 日期）
- 可导出 CSV
- **纯本地存储，不上云**

### F9 日志

- 全量收发记录：每条指令 + 应答 + 时间戳
- 异常自动标红
- 可导出 txt（FAE 分析用，就是我们这几天排查问题最需要的东西）

### F10 设置

| 项 | 说明 |
|---|---|
| SN 规则 | 前缀/位数/校验位 |
| 串口 | 端口、波特率、超时 |
| 烧录选项 | 成功后是否自动上锁、是否二次确认 |
| 文件路径 | counter.json / ledger.csv 位置 |
| 工号 | 操作员工号 |

配置存 `config.json`，改规则不用改代码。

## 4. 技术选型

| 方案 | 打包体积 | 依赖 | 风险 |
|---|---|---|---|
| **A. Python + tkinter + pyserial + PyInstaller**（推荐） | ~10 MB | tkinter 是 Python 自带；pyserial 可 vendored 进项目（纯 Python 免编译） | 低。断网可装，界面朴素但产线够用 |
| B. Electron + serialport | ~150 MB | serialport 要原生编译，可能装不上 | 中。界面现代但重，且依赖网络 |

**推荐 A**：产线工具优先看稳定和体积，tkinter 完全够。本机已有 Python 3.13.2。

产物：单个 `SnBurner.exe`，双击即用，目标机不用装 Python。

## 6. 待你确认的三件事

**① IMEI 怎么拿到？**
防重第一道防线的主键是 IMEI，但设备端目前串口不吐 IMEI（只在开机日志里有）。两个选择：

- **A**：设备端加一条指令（如 `R:ID`），一次返回 IMEI + chip_uid + SN —— 10 行 Lua 的事，**推荐**
- **B**：用 chip_uid 当主键（`R:SN` 已有，但需要设备端一起返回）
- **C**：不做台账查重，只靠计数器唯一性（弱一些，但设备换了号不会被发现）

**② SN 格式定哪个？**

| 方案 | 示例 | 特点 |
|---|---|---|
| 短横线分段 | `VK-2609-00042` | 人读友好 |
| 定长 16 位含校验 | `VK26090000042C` | 机器扫友好，能查出抄错一位 |

**③ 要不要「烧录后自动上锁」？** 建议开，防止现场被二次改写。
