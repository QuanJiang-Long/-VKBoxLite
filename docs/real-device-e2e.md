# 真机全流程跑测

脚本：`tools/real_device_e2e.js`（驱动真实 Electron 界面，不是 mock）

它是"带着界面跑一遍完整用户旅程"的自动化：枚举串口 → 打开 → 读信息 → 切档 →
读配置 → 加测试点 → 存配置 → 导出 → 导入 → 读实时值 → 内存探针 → 网络/MQTT →
sniff 推断 → 切回空闲 → 还原现场。每一步都点真实按钮、走真实 IPC / 串口，
所以能抓到"固件和界面没对上"的那类问题。

---

## 1. 测什么 / 不测什么

| 覆盖 | 不覆盖（脚本管不到，见第 7 节） |
| --- | --- |
| 串口打开/关闭、115200 链路 | 485 电气层：A/B 极性、共地、终端电阻、线长 |
| R:INFO 设备信息 | 掉电后配置是否保留（要真的断电） |
| 档位互斥切换、切档复位 | 长时间跑的内存爬坡 / 看门狗复位 |
| R:CFG / W:CFG 读写、分片上传 | 平台侧是否真的收到 MQTT 报文 |
| 导出/导入 JSON 回环 | 多从站并发、总线冲突、异常帧 |
| R:VAL 实时值（需从站） | 采集精度/量程标定 |
| R:MEM 内存连续块 | 4G 信号弱网重连 |
| R:NET / R:MQTT（需 4G） | — |
| sniff 推断（需总线流量） | — |

---

## 2. 跑之前（现场清单）

1. 模组烧好本仓库固件，USB 口在设备管理器里是一个 `COMx`。
2. 没有别的程序占着这个口：SSCOM、组态软件、另一个本工具实例、上次没退干净的
   Electron。**被占用时脚本会在第 2 步明确报"打开失败"**。
3. 485 接线：A/B 不接反、共地；长线或多从站时加 120Ω 终端电阻。
4. 从站地址 / 功能码 / 寄存器地址，和设备里"手动配置"的表一致，否则第 11 步会
   SKIP（读不到值），这不是固件问题。
5. 前端依赖已装：`cd frontend && npm install`（只为拿 Electron 二进制）。

## 3. 跑

```powershell
# 推荐：脚本自己拉起应用（会自动设 VKBOX_DOWNLOAD_DIR，导出不会弹原生保存框）
node tools/real_device_e2e.js --port COM32 --launch

# 也可以用已经在跑的应用（记得它启动时带了 --remote-debugging-port=9333
# 和 VKBOX_DOWNLOAD_DIR，否则导出会卡在系统保存对话框上）
node tools/real_device_e2e.js --port COM32
```

常用开关：

| 开关 | 作用 |
| --- | --- |
| `--launch` | 自己拉起 Electron 并带调试端口 |
| `--debug-port 9333` | 调试端口（默认 9333） |
| `--download-dir D:\xxx` | 导出落盘目录（默认 `%TEMP%\vkbox_e2e_dl`） |
| `--no-write` | 只读巡检，不写设备配置 |
| `--no-restore` | 切完空闲不还原配置（默认会导回去） |
| `--expect-slave` | R:VAL 没值算 FAIL（产线验收） |
| `--expect-net` | MQTT 未就绪算 FAIL（产线验收） |
| `--min-max-block 4096` | R:MEM 连续块下限（大配置场景调高） |
| `--keep` | 测完不关应用，方便手动复看 |

退出码：`0` 全 PASS/SKIP，`1` 有 FAIL，`2` 脚本/环境问题（连不上调试端口等）。

> Windows 控制台如果中文乱码，先 `chcp 65001`。

---

## 4. 判定语义

- **PASS**：这一步的软件链路通了。
- **FAIL**：该过的没过，需要排查（第 6 节）。
- **SKIP**：依赖外部条件，条件不满足属正常：
  - 第 11 步：没有 485 从站应答；
  - 第 13 步：没插卡 / 未注网 / 无 IP；
  - 第 14 步：MQTT 未配或平台不可达；
  - 第 15 步：总线上没有报文（从站不主动说话、主站没跑）。
  - 第 16 步：设备本来就在空闲，验证不了"切档复位"。

产线验收用 `--expect-slave --expect-net` 把 11/13/14 的 SKIP 升级成 FAIL。

## 5. 脚本做的事（19 步）

| # | 步骤 | 关键判定 |
| --- | --- | --- |
| 0 | 页面就绪 | 不是 mock 模式（有 `window.serial`） |
| 1 | 枚举串口 | 列表里出现 `--port` 指定的口；等列表稳定再选，避免刷新竞态 |
| 2 | 打开串口 | `S.open === true`，状态栏显示端口名 |
| 3 | 读设备信息 | SN 非空；真机要求长度 ≥ 8（IMEI 空只记备注） |
| 4 | 读运行模式 | R:MODE 有应答 |
| 5 | 切 manual | 点卡片 → 自动点确认框 → 模式变为 manual |
| 6 | 读 485 配置 | 状态栏出现"配置已读取"；记录波特率/行数 |
| 7 | 准备测试寄存器 | 设备已有配置就沿用；空表才加 `1 / uint16 / A1` |
| 8 | 保存配置 W:CFG | 状态栏"配置已保存"；真机等 40s（分片上传） |
| 9 | 导出 JSON | 落盘且能解析、寄存器非空 |
| 10 | 导入 JSON | 原生文件框被拦截并回填，导入成功 |
| 11 | 读实时值 | 表格里出现数值（需从站） |
| 12 | 内存 R:MEM | 最大连续块 ≥ `--min-max-block`（默认 2048B） |
| 13 | 网络 R:NET | status=1 且 ip≠`-`（需 4G） |
| 14 | MQTT R:MQTT | `ready=true`（需服务器/网络） |
| 15 | sniff 推断 | 推断表非空（需总线流量） |
| 16 | 切回 idle | 切档成功 + R:CFG 里寄存器已清空 |
| 17 | 还原现场 | 用第 9 步导出的文件导回，设备回到测试前的配置 |
| 18 | 关闭串口 | `S.open === false`，状态栏"未连接" |
| 19 | 页面错误 | 过滤 CSP 警告后应为 0 条 |

第 12/13/14 步没有界面入口，直接走页面的 `sendCmd`（R:MEM / R:NET / R:MQTT），
这是刻意的：它们本来就是排障探针。

## 6. FAIL 排查表

| 现象 | 先看这里 |
| --- | --- |
| 第 1 步：列表里没有 COMx | 驱动没装好 / 换 USB 口 / 设备管理器里是不是"未知设备" |
| 第 2 步：打开失败 | 端口被别的程序占着（含上一个没退的 Electron）；`--keep` 之后要手动关掉再跑 |
| 第 3 步：SN 没读到 | 固件没跑起来 / 波特率不是 115200 / 这是产线口不是应用口 |
| 第 5 步：没切到 manual | 看状态栏与 toast；platform 档切换会多问一次"清空平台配置"，脚本会自动确认 |
| 第 6 步：配置没读到 | 看状态栏文案；R:CFG 超时通常是串口被抢或设备在重启 |
| 第 8 步：保存失败 | 最常见是"设备腾不出接收窗口"→ 看第 12 步 R:MEM 的 max；max < 4096 时大配置会失败 |
| 第 9 步：导出目录没文件 | 应用不是用 `VKBOX_DOWNLOAD_DIR` 启动的，原生保存框把流程挡住了 → 用 `--launch` |
| 第 10 步：导入失败 | 确认应用是 manual 档；检查导出的 JSON 是否被手工改坏 |
| 第 12 步：max 太小 | 碎片化或配置太大；重启设备后再看一次，还小就是配置规模超了 |
| 第 19 步：页面有错误 | 一般是前端真实 bug，把错误文本带回仓库 |

---

## 7. 必须人工补的三项

1. **掉电保持**：跑完第 8 步（配置已保存）后给设备断电 10s 再上电，
   确认 SN/配置/MQTT 凭证还在，且能自动进入上次的 boot_mode。
   脚本无法控制电源，这一步只能人做。
2. **485 电气层**：A/B 反接、缺共地、缺终端电阻都可能"能通但偶发 CRC 错"，
   软件层测不出来。多从站时用示波器/总线分析仪看波形更稳。
3. **平台端到端**：第 14 步只能证明设备侧 MQTT ready。
   报文是否真的到了平台、字段对不对，要在平台侧看一次。

## 8. 和模拟器脚本的关系

两个脚本跑的是**同一份 journey**（`tools/e2e/journey.js`），只是目标串口不同：

```powershell
node tools/sim_e2e.js --webc 18921 --launch
```

模拟器没有从站、没有 4G，所以 11/13/14/15 必然 SKIP —— 这是正常的。
模拟器验证的是"软件链路"（传输、指令、配置读写、导入导出、UI 状态机），
真机额外验证电气层、时序、内存、网络、掉电。模拟器的预置步骤见
[`docs/simulator-e2e.md`](simulator-e2e.md)。

## 9. 留档建议

现场跑完把整屏输出贴进问题单，特别是有 FAIL 时：

- 每个 FAIL 行自带的 `stMsg` / `toast` 文案；
- 第 12 步的 `RET:MEM=...` 原始应答（max/fail 两个数最关键）；
- 第 3 步的版本号（`ver`）和 SN，便于对上固件分支。
