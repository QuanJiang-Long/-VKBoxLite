# 12-fix-11 —— 拓扑一次成串 + 每地址瘦身（2026-10-29）

## 为什么做这一轮

用户把设备烧到现场跑（SN VL20261019001，82 个地址），反馈"平台上只报了一部分数据"。
查日志找到根因：

```
W/user.iot topo_sig failed, skip this round: iot.lua:690: not enough memory for buffer allocation
```

`iot.lua:690` 就是拓扑拼串那行 `table.concat(props, ",")`。**连 8.3KB 的连续块都切不出来**
→ 拓扑一帧都没发出去（census `topo=0`）→ 平台没有物模型 → 用户只看到一部分数据。
这条链路每 30 秒失败一次（`bfail` 每次 +1），现场被它拖到池子 95%。

## 本轮做了什么（4 处 + 2 个新模块/测试）

| 改动 | 效果 |
|---|---|
| 拓扑一次成串（新 `lua/iot/topo.lua`） | 峰值连续需求 25.6KB → 8.6KB；总分配 -34%；指纹不再常驻 8.5KB |
| `build_topo` 不再给每行造小表 | 每轮少 33KB 瞬时垃圾（82 地址 × 406B × 2） |
| 数据点 6 字段 → 4 字段 | 每地址 -96B（conf/status 全项目没有读者） |
| 删掉 `aliasCache` | -6KB 一次性 + 每地址 -40B（Lua 短串本来就 intern） |
| JSON 应答只拼一次（`reply_json`） | R:STAT 每 5 秒少 2.3KB 垃圾 |
| 顺带修依赖图的误报 | iot.lua 注释里的 `require "iot/iot"` 被正则当成真 require → 改成单引号 |

实测（PC 模拟器）：
- 每地址常驻 **555B → 475B**（64 地址 34.69KB → 29.69KB）
- 拓扑构建总分配 **65026 → 42641 字节（-34%）**
- 代码体积 300.2 → 303.9 KB（+iot/topo 2.6KB，+cmd 的 reply_json 1.4KB，-collector 0.4KB）

## 关键结论：**"路 B 全列式"的性价比不如"合并/瘦身"**

算过的账（每地址）：

| 方案 | 每地址 | 说明 |
|---|---|---|
| 现状（12-fix-9 后） | 555 B | 推断行 230 + 数据点 230 + 历史 24 + 串 32 + 索引 |
| 路 B 全列式 | ~280 B | 14 个字段 × 16B + 两级索引 ≈ 100B，**索引把省下的吃回去** |
| 数据点合并进推断行 | ~300 B | 但行要加 ts → 9 字段 → 哈希槽 8→16 个（203→363B），净只剩 -87B |
| **数据点瘦成 4 字段（本轮）** | **475 B** | 哈希段 8 槽→4 槽，直接减半，**零风险** |

**Lua 表的两种布局各占 24B/字段（哈希节点）vs 16B/元素（数组）**，哈希段按 2 的幂走：
≤4 字段 = 4 槽，5~8 字段 = 8 槽 —— 所以**减少字段数**的收益比换布局大，
而且不用碰前端契约。列式留到 12-fix-12（128 地址满配时再省一轮）。

## 为什么没做的

- **pullcfg 惰性化**：12-fix-8 已经做了（`get_pullcfg()`）✓
- **lbsLoc2 惰性化**：LBS 每 30 分钟请求一次，模块照样会加载 → 白改
- **iot.lua 拆分（-14KB）**：平台配置拉取链路**没有任何模拟器测试**，风险最高，
  放最后且要补测试。本轮先用拓扑 + 每地址的改动腾出余量。

## 顺带查出来的两个真 bug

1. **32 位固件 `os.time()*1000` 整数回绕**：实测 = **-2036609728**（负数）。
   `send_meta` / `send_topo` 两处的 ts 都是这个值。**本轮已修**（用户拍板）：
   改用 `MqttUtil.ms_of(os.time())`（秒 → 13 位毫秒串），**ts 的 JSON 类型
   从数字变成字符串**（U4 的 ts 本来就是字符串、平台在收 ✓）。
2. **物模型 dataType 一直是 uint16**：`build_nodes` 读 `r.dtype_summary`，
   而 12-fix-6 改成累加器之后行里没这个字段了 → 32bit 寄存器被报成 uint16。
   **用户决定先不修**（修它 = 动平台的物模型契约，平台收不收 uint32/int32/
   float32 没验过），另开一次改 + 单独验平台。

## 教训

- **平台的物模型契约 = 字节级的**。拓扑的 JSON 一个字段都不能多不能少 →
  重构必须配"逐字节对比"测试（`tests/lua/test_topo.lua` 把老格式串抄了一份当基准）。
- **模拟器里 uart 是 C 库的只读表**，换不掉 `write`，截不到串口输出 →
  测试钩子要露在模块里（`M._stat_reply()` / `M._json_reply_str()`），
  这是项目里已有的惯例（`M.poll_loaded()`）。
- **项目的静态检查会拦 `%08x`**（check_lua.py 判"32 位固件不安全"）→ 指纹用十进制串。
- **依赖图工具认双引号**：`require "x"` 写在注释里也会被当成真依赖 →
  注释里改用单引号。
